================================================================================
                        CAMBIOS EN BASE DE DATOS
================================================================================

IMPORTANTE: Los siguientes campos son REQUERIDOS en las tablas:

1. TABLA: productive_units
   - person_id (INT, NOT NULL) - ID del usuario que crea el área
   - sector_id (INT, NOT NULL) - ID del sector (usar valor por defecto: 1)
   - farm_id (INT, NOT NULL) - ID de la finca (usar valor por defecto: 1)
   - name (VARCHAR, UNIQUE) - Nombre único del área
   - description (TEXT, NULLABLE) - Descripción del área

   COMANDO SQL PARA VERIFICAR:
   ```sql
   DESCRIBE productive_units;
   ```

2. TABLA: infrastock_categories
   - name (VARCHAR, UNIQUE) - Nombre único de la categoría
   - type (ENUM: 'supply', 'tool') - Tipo de categoría

3. TABLA: equipments (insumos)
   - inventory_id (INT, NOT NULL) - ID del inventario
   - name (VARCHAR, NOT NULL) - Nombre del insumo
   - amount (INT, NOT NULL) - Cantidad
   - price (DECIMAL, NOT NULL) - Precio
   - category_id (INT, NOT NULL) - ID de la categoría
   - labor_id (INT, NOT NULL) - ID de la labor

4. TABLA: tools (herramientas)
   - inventory_id (INT, NOT NULL) - ID del inventario
   - labor_id (INT, NOT NULL) - ID de la labor
   - amount (INT, NOT NULL) - Cantidad
   - price (DECIMAL, NOT NULL) - Precio
   - category_id (INT, NOT NULL) - ID de la categoría

5. TABLA: warehouse_movements (préstamos/devoluciones)
   - productive_unit_warehouse_id (INT, NOT NULL) - ID de área/bodega
   - movement_id (INT, NOT NULL) - ID del elemento
   - item_type (ENUM: 'equipment', 'tool') - Tipo de elemento
   - user_id (INT, NOT NULL) - ID del usuario
   - role (ENUM: 'Préstamo', 'Devolución') - Tipo de movimiento

6. TABLA: users
   - person_id (INT, NOT NULL) - ID de la persona
   - email (VARCHAR, UNIQUE) - Email único
   - password (VARCHAR, NOT NULL) - Contraseña hasheada
   - nickname (VARCHAR) - Nombre completo
   - email_verified_at (TIMESTAMP) - Fecha de verificación

7. TABLA: people
   - first_name (VARCHAR, NOT NULL) - Nombre
   - first_last_name (VARCHAR, NOT NULL) - Primer apellido
   - second_last_name (VARCHAR, NULLABLE) - Segundo apellido
   - document_type (VARCHAR, NOT NULL) - Tipo de documento
   - document_number (VARCHAR, UNIQUE) - Número de documento único
   - telephone1 (VARCHAR, NULLABLE) - Teléfono
   - address (TEXT, NULLABLE) - Dirección

================================================================================
                        CONFIGURACIÓN REQUERIDA
================================================================================

1. SOFT DELETES:
   Asegúrate de que las siguientes tablas tengan soft deletes habilitados:
   - users (deleted_at)
   - productive_units (deleted_at)
   - infrastock_categories (deleted_at)
   - equipments (deleted_at)
   - tools (deleted_at)
   - warehouse_movements (deleted_at)

2. RELACIONES DE BASE DE DATOS:
   Verificar que existan las siguientes relaciones:
   - users -> person (belongsTo)
   - users -> roles (belongsToMany)
   - productive_units -> person (belongsTo)
   - equipments -> category (belongsTo)
   - equipments -> labor (belongsTo)
   - equipments -> inventory (belongsTo)
   - tools -> category (belongsTo)
   - tools -> labor (belongsTo)
   - tools -> inventory (belongsTo)
   - warehouse_movements -> user (belongsTo)
   - warehouse_movements -> tool (belongsTo)
   - warehouse_movements -> equipment (belongsTo)
   - warehouse_movements -> productiveUnitWarehouse (belongsTo)

================================================================================
                        INSTRUCCIONES PARA COMPAÑEROS
================================================================================

1. ANTES DE TRABAJAR:
   - Hacer backup de la base de datos
   - Verificar que todas las tablas tengan los campos requeridos
   - Comprobar que las relaciones estén correctamente configuradas

2. SI NECESITAN MODIFICAR LA BASE DE DATOS:
   - Usar migraciones de Laravel en lugar de cambios directos
   - Verificar que los campos únicos estén configurados
   - Asegurar que los campos NOT NULL tengan valores por defecto

3. SI HAY ERRORES DE VALIDACIÓN:
   - Revisar los controladores para ver las reglas de validación
   - Verificar que los campos requeridos estén presentes en los formularios
   - Comprobar que los tipos de datos coincidan entre BD y formularios

4. SI LOS MODALES NO FUNCIONAN:
   - Verificar que Alpine.js esté cargado correctamente
   - Comprobar la sintaxis de Alpine.js en las vistas
   - Revisar los z-index en el CSS del layout

5. SI LA PAGINACIÓN NO FUNCIONA:
   - Verificar que el método paginate() esté siendo usado en los controladores
   - Comprobar que las vistas tengan {{ $items->links() }}
   - Asegurar que no haya conflictos con JavaScript de filtros


```bash
php artisan cache:clear
php artisan config:clear
php artisan view:clear
php artisan route:clear
```

Para regenerar autoload:
```bash
composer dump-autoload
```
